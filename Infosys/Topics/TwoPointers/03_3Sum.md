# 3Sum

## Difficulty
Medium

## Probability
★★★★★

## Asked In

## Topic
Two Pointers / Arrays / Sorting

## Pattern
Opposite Ends (Collision) with Fixed Anchor

## Problem Statement
Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set **must not contain duplicate triplets**.

## Constraints
- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## Input
- `nums` vector of integers.

## Output
- Return a vector of vectors containing the triplets.

## Sample Test Cases

**Example 1:**
```
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation: 
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
The distinct triplets are [-1,0,1] and [-1,-1,2].
```

**Example 2:**
```
Input: nums = [0,1,1]
Output: []
Explanation: The only possible triplet does not sum up to 0.
```

**Example 3:**
```
Input: nums = [0,0,0]
Output: [[0,0,0]]
Explanation: The only possible triplet sums up to 0.
```

## Edge Cases
- All zeroes array `[0, 0, 0, 0, 0]`. Should only return ONE `[0,0,0]`.
- Array has fewer than 3 elements.

## Intuition
The naive approach is 3 nested loops, which takes $O(N^3)$ time and will TLE.
We can optimize this to $O(N^2)$ using the **Two Pointers** technique!

The trick is to **sort the array first**.
Sorting takes $O(N \log N)$.
Once sorted, we can iterate through the array. For every element `nums[i]`, we treat it as a **fixed anchor**.
The problem then reduces exactly to **Two Sum II**: We need to find two elements in the remaining array (`from i+1 to end`) that sum up to `-nums[i]` (so the total sum is 0).

**How to avoid duplicate triplets?**
Since the array is sorted, identical elements will be adjacent.
1. When selecting the anchor `nums[i]`, if `nums[i] == nums[i-1]`, we skip it! We already evaluated all triplets starting with this number.
2. When the Two Pointers `left` and `right` find a valid triplet, we must advance both pointers, but we must ALSO skip any adjacent duplicates for `left` and `right` to avoid pushing the exact same triplet to our results!

## Optimal Approach (Sorting + Two Pointers)
**Detailed explanation:**
1. Sort the array.
2. Loop `i` from `0` to `n - 3`:
   - If `i > 0 && nums[i] == nums[i-1]`: `continue` (Skip duplicate anchors).
   - If `nums[i] > 0`, break! (Since the array is sorted, if the anchor is positive, all numbers to its right are also positive, so it's impossible to sum to 0).
   - Set `left = i + 1`, `right = n - 1`.
   - While `left < right`:
     - `sum = nums[i] + nums[left] + nums[right]`.
     - If `sum == 0`:
       - Push `{nums[i], nums[left], nums[right]}` to results.
       - Increment `left` and skip duplicates: `while (left < right && nums[left] == nums[left - 1]) left++;`
       - Decrement `right` and skip duplicates: `while (left < right && nums[right] == nums[right + 1]) right--;`
     - If `sum < 0`: `left++`.
     - If `sum > 0`: `right--`.
3. Return results.

**Time Complexity:** $O(N \log N)$ for sorting + $O(N^2)$ for the nested loops = $O(N^2)$.
**Space Complexity:** $O(1)$ auxiliary space (excluding the output array).

## C++ Solution

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> result;
        int n = nums.size();
        
        // 1. Sort the array to use two pointers and easily handle duplicates
        sort(nums.begin(), nums.end());
        
        for (int i = 0; i < n - 2; i++) {
            // Optimization: If the smallest number is positive, sum can never be zero
            if (nums[i] > 0) break;
            
            // Skip duplicate anchor elements
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            
            int left = i + 1;
            int right = n - 1;
            
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                
                if (sum == 0) {
                    result.push_back({nums[i], nums[left], nums[right]});
                    
                    // Move both pointers inward
                    left++;
                    right--;
                    
                    // Skip duplicates for the left pointer
                    while (left < right && nums[left] == nums[left - 1]) {
                        left++;
                    }
                    
                    // Skip duplicates for the right pointer
                    while (left < right && nums[right] == nums[right + 1]) {
                        right--;
                    }
                } else if (sum < 0) {
                    left++; // Need a larger sum
                } else {
                    right--; // Need a smaller sum
                }
            }
        }
        
        return result;
    }
};
```

## Dry Run
`nums = [-1, 0, 1, 2, -1, -4]`
- Sorted: `[-4, -1, -1, 0, 1, 2]`.
- `i=0` (`-4`): `left=1 (-1)`, `right=5 (2)`. Sum = `-3`. Need larger, `left++`.
  - Max sum with `-4` is `-4 + 1 + 2 = -1 < 0`. Loop finishes.
- `i=1` (`-1`): `left=2 (-1)`, `right=5 (2)`. Sum = `0`. FOUND! `[-1, -1, 2]`.
  - `left++` -> `3 (0)`. `right--` -> `4 (1)`.
  - `left=3 (0)`, `right=4 (1)`. Sum = `0`. FOUND! `[-1, 0, 1]`.
  - `left++`, `right--` finishes loop.
- `i=2` (`-1`): `nums[2] == nums[1]`. Duplicate anchor! Skip!
- `i=3` (`0`): `left=4 (1)`, `right=5 (2)`. Sum = `3 > 0`. `right--`. Finishes.
- `i=4` (`1`): Anchor `> 0`. Break!
- Output: `[[-1,-1,2], [-1,0,1]]`.

## Common Mistakes
- **Using a HashSet of vectors to remove duplicates:** Pushing triplets into a `set<vector<int>>` and returning it technically works, but it adds massive overhead and is highly penalized in SP interviews. You MUST skip duplicates via pointer arithmetic manually to achieve true $O(N^2)$ time with $O(1)$ space.
